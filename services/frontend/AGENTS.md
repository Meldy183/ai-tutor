# Правила frontend

Дополняют [корневой AGENTS.md](../../AGENTS.md) для `services/frontend/` и обязательны для разработчиков и агентов. Это соглашения приложения: не заменяйте их общими шаблонами React-проектов без решения команды.

## Перед изменением

Стек и запуск — в [README](README.md). Перед правкой изучите соседний маршрут или компонент с похожей задачей и ближайшие тесты. Сохраняйте существующие границы слоёв и стиль импортов.

## Структура и границы слоёв

Фронтенд организован по Feature-Sliced Design. `src/bootstrap/` — согласованное
имя верхнего app-layer alias; не создавайте параллельные `src/app/` или
`src/application/`. `src/routes/` остаётся тонким техническим реестром TanStack
Router вне FSD layers, а сгенерированный `src/routeTree.gen.ts` не редактируется.

| Путь             | Ответственность                                                                                                                                                                                                                               |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/bootstrap/` | Entrypoint, composition root, providers и глобальные стили.                                                                                                                                                                                   |
| `src/pages/`     | Страницы с уникальной экранной композицией: trainer, learning-trainer, mode-selection, admin-courses и competency-map.                                                                                                                        |
| `src/widgets/`   | Блоки, которые действительно переиспользуются страницами: admin-course-detail-shell, course-graph и result-report.                                                                                                                            |
| `src/features/`  | Пользовательские действия: auth, diagnostic-session, subject-selection, import-competency-map (материалы курса), course-graph-build, import-learning-competency-map, learning-diagnostic-session, learning-plan и learning-subject-selection. |
| `src/entities/`  | Предметные модели и принадлежащие им API: user, assessment, diagnostic-session, subject, competency-map (материалы курса), course-graph, learning-competency-map, learning-diagnostic-session, learning-plan и learning-subject.              |
| `src/shared/`    | Общий транспорт, браузерные адаптеры, локализация и UI без предметной ответственности.                                                                                                                                                        |
| `src/routes/`    | Тонкая регистрация URL и подключение page API; `__root.tsx` передаёт управление bootstrap shell.                                                                                                                                              |

- Слои импортируют только нижние слои: `bootstrap → pages → widgets → features → entities → shared`.
- Slices одного слоя изолированы. Исключение для взаимных entity типов — только минимальный `@x/<consumer>` API. Публичный API slice находится в `index.ts`; глубокие импорты между слайсами запрещены. Внутри slice используйте относительные импорты.
- `shared` не импортирует верхние слои. Импорт другого shared-сегмента идёт через его `index.ts`.
- Не создавайте слой или widget без отдельной ответственности. Query hooks и предметные порты размещайте у owning feature/entity, а HTTP-адаптеры подключайте per-slice через `bootstrap`; не помещайте общий aggregate зависимостей в `shared`.
- Чистые сценарии в `model`/`lib` остаются без React и HTTP. QueryClient lifecycle принадлежит использующим его hooks и providers. Тестовые fake-порты используют те же контракты, что и HTTP-адаптеры.

## Маршруты и компоненты

- Создавайте маршруты в `src/routes/` через `createFileRoute` и используйте
  фактический путь в его строковом литерале.
- `src/routeTree.gen.ts` генерируется плагином TanStack Router. Никогда не
  редактируйте его вручную; после изменения маршрутов Vite обновит файл.
- Переходы выполняйте с `useNavigate`, а не через ручные изменения URL.
- Для стандартной разметки предпочитайте компоненты Radix Themes. Нативный элемент
  используйте, когда Radix Themes не покрывает задачу.
- У каждого экрана должны быть понятные состояния: загрузка, ошибка с
  возможностью повторить действие, пустой результат и успешное содержимое.
  Добавляйте эти состояния, когда экран начинает получать данные.
- Не скрывайте ошибки пустым экраном и не подменяйте ошибку пустым состоянием.

## Данные и React Query

- Query hooks располагаются рядом с owning feature/entity и получают источники через context/provider этого slice. Именуйте hook по ресурсу с префиксом `use`; query hook заканчивается на `Query`, например `useLessonsQuery`.
- Query keys стабильны, сериализуемы и включают параметры, меняющие результат. Храните их у владельца ресурса, не собирайте все предметные ключи в `shared`.
- Изменения данных оформляйте через `useMutation`; после успеха инвалидируйте затронутые query-ключи. Не меняйте кэш из компонентов вручную без причины.
- Не создавайте `QueryClient` во время рендера экрана. Используйте `createQueryClient` и `AppProviders` из `src/bootstrap/providers.tsx`. В тестах используйте общий wrapper `tests/support/query-wrapper.tsx`, а чистые сценарии проверяйте передачей fake-портов без module-mock.

## Локализация и доступность

- Любая новая пользовательская строка добавляется в `src/shared/i18n/i18n.ts` и
  выводится через `t('namespace.key')`. Не оставляйте новый текст литералом в
  JSX, включая `placeholder`, `aria-label` и сообщения об ошибках.
- Группируйте ключи по назначению (`navigation`, `query`, `routes`), а не по
  названию компонента. Используйте осмысленные английские ключи; значения для
  текущей локали — русские.
- Выбирайте семантические элементы и обеспечивайте доступное имя для каждого
  интерактивного элемента. Иконка без видимого текста должна иметь `aria-label`;
  декоративная иконка — `aria-hidden`.
- Сохраняйте корректную иерархию заголовков: на экране есть один `h1`, карточки
  и секции используют следующие уровни.
- Проверяйте клавиатурную навигацию и не заменяйте `button`/`a` кликабельными
  `div`.

## Стили

- Стили компонента или маршрута храните рядом с ним в `*.module.scss` и
  импортируйте как `styles`. Не используйте строковые глобальные имена классов.
- `src/bootstrap/global.scss` предназначен только для глобальной основы приложения:
  CSS-переменных, фона, базовой высоты и общих медиа-правил. Не добавляйте туда
  стили конкретных экранов.
- Используйте токены Radix (`--space-*`, `--gray-*`, `--accent-*`) и `--app-*`.
  Новый цвет, отступ или тень,
  повторяющиеся в двух и более местах, оформляйте токеном в `global.scss` с
  вариантом для тёмной темы, если он нужен.
- Не ломайте светлую или тёмную тему жёстко заданным цветом без обоснования.
  Проверяйте контраст текста, элементов управления и состояний ошибки.
- Не используйте inline-стили, если свойство можно выразить существующим классом
  или CSS-переменной. Допустимое исключение — действительно динамическое
  значение, зависящее от данных.

## Тесты и проверка

- Для нового пользовательского поведения добавляйте или обновляйте тест Vitest
  в `tests/`, зеркально повторяя путь модуля из `src/` (`*.test.ts` / `*.test.tsx`).
  Общую настройку храните в `tests/setup.ts`, вспомогательные модули — в
  `tests/support/`; `src/` содержит только код приложения. Тестируйте наблюдаемый результат:
  роли, доступные имена, текст, переход или отрисованные данные — не детали
  реализации.
- Для маршрутов используйте `createMemoryHistory`, `createRouter` и
  `RouterProvider`, как в `tests/routes/routes.test.tsx`. Для query-hooks и
  компонентов, использующих их, оборачивайте тест в `QueryClientProvider` с
  `createQueryClient`.
- Не отключайте TypeScript, ESLint или тесты ради прохождения сборки. Исправьте
  причину или кратко зафиксируйте блокирующее внешнее ограничение в PR.
- Выбирайте объём проверок по [корневым правилам](../../AGENTS.md#локальные-проверки-и-нагрузка).
- Полный локальный набор из `services/frontend/`:

  ```bash
  npm run format:check
  npm run lint
  npm run typecheck
  npm test -- --run --maxWorkers=1
  npm run build
  ```

- Полный frontend CI дополнительно выполняет Playwright E2E и сборку Docker-образа. Локально запускайте нужные E2E с `npm run test:e2e -- <файл> --workers=1`, когда изменение затрагивает соответствующий сквозной сценарий. Не запускайте E2E одновременно с другими проверками или сборкой.

## Правила работы агентов

- Предлагайте минимальное изменение, сохраняющее текущие соглашения.
- Не изменяйте сгенерированные файлы, lock-файлы, зависимости, конфигурацию
  сборки или общие токены, если задача этого прямо не требует.
- Не подменяйте рабочий источник данных моками и не меняйте публичные контракты
  источников данных без одновременного обновления всех реализаций и тестов.
- Не выполняйте массовые рефакторинги вместе с продуктовой задачей. Вынесите их
  в отдельное предложение, если они не нужны для корректности текущей правки.
- В итоговом сообщении указывайте изменённые файлы, выполненные команды
  проверки и их фактический результат. Если проверка не запускалась, прямо
  назовите причину.
