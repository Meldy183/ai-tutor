# Авторские задания в карте Geek

Книга загружается общей кнопкой импорта карты на странице подготовки курса. В XLSX нужны минимум два листа: первый — задания Geek, второй — учебной диагностики. Имя листа не определяет назначение. Дополнительные справочные листы не участвуют в обработке. Отдельного CSV/однолистового импорта `/learn` нет.

## Формат первого листа

| Колонка | Использование |
| --- | --- |
| Компетенция / Субкомпетенция | Вместе с составляющей определяет группу ОР |
| Составляющая | Принадлежность ОР и единица зачёта для последующего обучения |
| Образовательный результат | Название ОР, сохраняется в полном банке |
| Таксономия / Уровень по Блуму | Определяет выбор основного и базовых ОР |
| Важность | Целое число 1–5; разрешает ничьи при отборе |
| Что должно войти в тест | TRUE допускает ОР к отбору вопросов; FALSE не удаляет ОР из банка обучения |
| Свидетельство | Необязательный контекст, если нет отдельного текста темы |
| Текст темы | Необязательная теория для контекста задания |
| Задание 1, 2, … | Варианты задания одного ОР; при прохождении выбирается один |
| Критерии оценивания… | Сопоставляются заданиям по порядку колонок. Эталон и критерии относятся только к своему варианту |
| ID темы / Пререквизиты | Не управляют графом и обходом; явные связи из КК не используются |

Компетенции, составляющие и ОР первого и второго листов могут различаться. Общими являются формат хранения и алгоритмы, а не названия и наборы вершин. Задания, эталоны и критерии листов не объединяются по похожим названиям.

## Отбор и полный банк

Обычная и авторская карта используют один алгоритм: в каждой составляющей с минимум тремя подходящими ОР основное выбирается по наибольшему Блуму, затем важности и порядку; два базовых — по наименьшему Блуму, затем важности и порядку. Каждый выбранный ОР может иметь несколько вариантов задания.

Все ОР и задания сохраняются, в том числе не выбранные для экзамена и помеченные FALSE. Для оставшихся ОР достаточно принадлежности составляющей: дополнительные рёбра между ними не строятся. Несколько заданий одного ОР не заменяют три различных ОР для отбора.

Авторская книга с колонками зависимостей не включает отдельный алгоритм. Даже если в ней 16 вопросов, в экзамен войдут только выбранные ОР; остальные остаются в банке. Однолистовые файлы и JSON-снимок `examples/geek-authored-16/graph.json` из исторической demo-ветки не являются форматом текущего XLSX-импорта.

## Оценка и обучение

Основное задание оценивается в 0/1/2, базовое — в 0/1. Модель возвращает балл и основания, код применяет ограничение за помощь и выбирает следующий шаг. Текст критериев преподавателя уточняет содержание ответа; собственные баллы рубрики и К1–К4 не являются выходной шкалой. A–D остаётся только у курса.

При отсутствии критериев применяется общая инструкция проверки корректности и покрытия вопроса. Администратор получает предупреждение и может исключить такие задания из экзамена. Исключение не удаляет ОР из полного банка и сохраняет ID оставшихся заданий; пустой экзамен не публикуется.

Основное задание на 2 либо суммарный результат заданных заданий от 90% засчитывает все ОР составляющей. В незачтённой составляющей обучению нужны все ОР, кроме решённых на максимум, включая незаданные. Будущее обучение после Geek использует его первый лист; переход из итога Geek к обучению пока не добавлен.

## Загрузка и версии

`POST /api/v1/exam/admin/subjects/{subject_id}/graph/competency-map` принимает multipart `file` до 25 МиБ и обязательный `X-Expected-Learning-Revision` с актуальной учебной ревизией, либо 0 при первой загрузке. При устаревшей ревизии — 409 без замены карты. Книга без второго листа — 422 `UNIFIED_COMPETENCY_MAP_REQUIRED`.

Оба листа и задача подготовки Geek сохраняются одной транзакцией. Учебная версия активируется сразу, Geek остаётся на предыдущем графе до успешной подготовки нового. Ошибка подготовки не отключает обучение. Публикация изменённого Geek-графа отменяет его активные сессии; завершённые результаты сохраняются.
