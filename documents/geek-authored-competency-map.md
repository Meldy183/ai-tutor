# Авторская карта Geek: 16 согласованных вопросов

Подготовлена для импорта графа через «Импортировать карту компетенций» на экране материалов экзамена. Карта загружается одной двухлистовой XLSX-книгой и одним импортом: первый лист — для экзамена Geek, второй — для учебной диагностики. Отдельной ручки импорта в `/learn` нет.

## Что использует текущий импорт

Книга должна содержать оба листа, иначе импорт отклоняется. Первый лист по порядку — Geek, второй — учебная диагностика; имена листов не участвуют в выборе. Читаются только первые два листа, остальные импорт не открывает. Колонки второго листа разбирает парсер учебной диагностики, здесь они не описаны. Пути «компетенция → составляющая → ОР» обоих листов должны совпасть; расхождение отклоняет импорт. В пути входят все строки с ОР, в том числе с FALSE и без заданий. Запрос передаёт ожидаемую активную ревизию карты в заголовке `X-Expected-Learning-Revision` (0, если карты ещё нет). Подробности запроса, ошибок и сохранения — [backend README](../services/backend/README.md#экзаменационная-карта).

Ниже колонки первого листа.

| Колонка | Использование Geek |
| --- | --- |
| Компетенция / Субкомпетенция | Вместе с составляющей определяет группу обычной карты и путь для сопоставления со вторым листом |
| Составляющая | Значения обязательны; обычная карта выбирает главное и два базовых задания внутри составляющей |
| Образовательный результат | Название вершины, provides; в тексте темы идёт строкой «Образовательный результат: …», если нет текста темы |
| Таксономия / Уровень по Блуму | В обычной карте определяет главное и базовые задания; значения проверяются и в явной карте |
| Важность | Разрешает ничьи при отборе; целое число 1–5 |
| Что должно войти в тест | TRUE включает строку; FALSE или пусто исключает |
| Свидетельство | Необязательный контекст, когда нет отдельного текста темы |
| Задание 1, 2, … | Вопросы без переформулирования; несколько заданий одной строки — случайные варианты одной темы |
| Критерии оценивания… | Сопоставляются заданиям **по порядку колонок**, а не по числу в названии. Строки эталона (например «Эталон», «Допустимо») добавляются к тексту темы как контекст. Строка, начинающаяся с «Балл», «Аналитическая рубрика», «К1», числа с «балл» или тире, и все строки после неё передаются оценщику как ориентир, что считать полным ответом. Если ячейка пуста или колонки критериев нет, подставляется общая рубрика корректности и покрытия вопроса (`coursegraph.DefaultAssessmentGuidance`); админке возвращаются строки и задания подстановки |

В примере Geek не использует «Уровень темы», DOK, ALDs, раздел/компетенции РПД, ОС, соответствие целям, тему/недели/материалы, «Код», примечания и листы после второго. Колонка с темами/неделями сама по себе не даёт оценщику теорию.

## Оценивание

Тему оценивает модель по шкале темы: верхний уровень — 0, 1 или 2 балла, любая тема ниже — 0 или 1. Критерии строки не задают свою числовую шкалу: они только описывают, что считать полным ответом. К1–К4, числовые рубрики тем и буквы A–D у тем не используются; буква A–D остаётся только у оценки курса по проценту нормализованных баллов. Правила шкалы и помощи — в [README](../README.md).

## Явный граф

Обычная карта сохраняет три ОР на составляющую: главный (наивысший уровень по Блуму, затем важность) и два самых простых как его базовые; остальные в обход не входят. Составляющая, в которой меньше трёх ОР с TRUE и заданием, пропускается. Чтобы не терять авторские вопросы и не придумывать дублирующие задания, есть явно включаемый формат:

- **ID темы** и **Пререквизиты** должны присутствовать вместе. Тогда каждая включённая строка становится вершиной, без отбора трёх ОР. ID обязателен и уникален. Пререквизиты — ID через точку с запятой, запятую или перенос строки; пустая ячейка означает отсутствие зависимостей.
- **Текст темы** необязателен: позволяет передать исходную теорию, а не только формулировку ОР. Эталон из критериев добавляется к ней; рубрика не смешивается с теорией.
- Неизвестные зависимости, ссылки на исключённые строки, дубликаты ID и циклы отклоняются с указанием ячейки/строки. Половина пары заголовков не включает отбор трёх ОР молча: книга отклоняется.

Готовый граф авторского демо из 16 тем (по одному вопросу на тему) лежит в ветке `demo/geek-authored-16`: `examples/geek-authored-16/graph.json` с вопросами, теорией, критериями и зависимостями; инструкция рядом в README. Это снимок графа, а не файл для загрузки через XLSX-импорт. Критерии допускают разумные внешние примеры, требуют все запрошенные части и не штрафуют за разговорную форму. Даты, имена, примеры из лекции и дословность не требуются, если вопрос их не просит.

Все 16 тем входят в граф. Это не обещание задать каждому студенту все 16 вопросов: действующий обход по-прежнему может зачесть базовые темы по сильному ответу на вышестоящую.

## Применение

Файл загружается кнопкой импорта как двухлистовая книга (см. выше). Импорт сохраняет новую ревизию карты, делает её активной и ставит подготовку переформулировок и озвучки; Geek сохраняет прежний опубликованный граф до успешной подготовки нового. Наличие критериев не устраняет противоречий самой карты: соответствие задания и его критериев должен проверить преподаватель.
